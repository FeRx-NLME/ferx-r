- **ferx now builds against ferx-core `b259dd10`**, up from `32dbb309` (#669,
  which supersedes #664 and carries its changes). These engine changes reach
  R as new behaviour; the fixes are listed under Bug fixes:

  - **ODE fits run on compiled code and are faster, with identical estimates
    and OFV** (`mm_oral` 1.66 s -> 1.00 s on one core before the last of the
    three, a 40-subject TMDD fit 365 s -> 172 s)
    ([ferx-core #2454](https://github.com/FeRx-NLME/ferx-core/pull/2454),
    [#2456](https://github.com/FeRx-NLME/ferx-core/pull/2456),
    [#2468](https://github.com/FeRx-NLME/ferx-core/pull/2468)). The `[odes]`
    right-hand side is compiled to machine code (Cranelift) the first time a
    fit evaluates it, and the exact gradient and the covariance step's exact
    Hessian run on it too. Setting the environment variable
    `FERX_NO_RHS_JIT=1` keeps the interpreter; a platform Cranelift cannot
    target falls back to it on its own. Closed-form models are unchanged.
  - **A profiled fit's covariance step is exact wherever the outer gradient
    is analytic**
    ([ferx-core #2109](https://github.com/FeRx-NLME/ferx-core/issues/2109),
    [#2417](https://github.com/FeRx-NLME/ferx-core/pull/2417)): its standard
    errors now match the unprofiled fit's to about 1e-8 (they were off by the
    finite-difference stencil's 0.1-0.5%), and the step is about 25x faster
    on a 100-study placebo model. A new warning names subjects whose level
    blocks fell back to finite differences. Under `gradient = "fd"` or
    `analytic_cov_hessian = FALSE` the step is unchanged.
  - **New warning `W_ZERO_DV_MAGNITUDE_ONLY`**
    ([ferx-core #2459](https://github.com/FeRx-NLME/ferx-core/pull/2459)):
    `ferx_fit()` and `ferx_model_validate(data = )` warn when observations with `DV = 0` are
    scored by a proportional, power or zero-additive error model, where a fit
    can stop at a wrong optimum that still reports converged. It suggests an
    additive component, removing the rows, or `CENS = 1` with
    `bloq_method = "m3"`.
  - **An edited model file is refused with `e$code == "E_FIT_INPUT_CHANGED"`**
    by `ferx_sir()`, `ferx_covariance()` and `ferx_calc_npde()`, as an edited
    data file already was
    ([ferx-core #2027](https://github.com/FeRx-NLME/ferx-core/issues/2027),
    [#2451](https://github.com/FeRx-NLME/ferx-core/pull/2451)). The `model
    hash mismatch` refusal had no code. The message is unchanged.
  - **A `profile`d level block may be read through an `if` on data, or more
    than once**
    ([ferx-core #2114](https://github.com/FeRx-NLME/ferx-core/issues/2114),
    [#2432](https://github.com/FeRx-NLME/ferx-core/pull/2432)):
    `B = if (WT > 70) PLACEBO * 2 else PLACEBO` and a sum of reads were
    refused with `E_PROFILE_NOT_LINEAR`.
  - **`method = "gn"`, `"gn_hybrid"` and `optimizer = "trust_region"` now
    report `W_EBE_START_DEPENDENT`**
    ([ferx-core #2097](https://github.com/FeRx-NLME/ferx-core/issues/2097),
    [#2430](https://github.com/FeRx-NLME/ferx-core/pull/2430)), as the NLopt
    optimizers do. `trust_region` reports the best of the cold and seeded
    EBE re-solves; `gn` and `gn_hybrid` run the check for diagnosis only and
    keep their own EBEs and OFV.
