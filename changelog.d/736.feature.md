- **`fit$status` and `fit$status_reasons`: a usability verdict beside
  `converged`** (#736, ferx-core#2799). `fit$status` is `"converged"`,
  `"converged_with_issues"` or `"not_converged"`, and `fit$status_reasons`
  lists what qualifies it, in a fixed order: `evaluation_only`, `budget_spent`,
  each critical warning code, `covariance_failed`, and
  `collapsed_at_guard: <names>`. Both come from ferx-core, and the `STATUS:`
  line in `print(fit)` now prints them as ferx-core spells them
  (e.g. `CONVERGED WITH ISSUES   (covariance_failed, collapsed_at_guard: ETA_KA)`).
  That tail used to list the critical warning categories R found. The two new
  inputs are also on the fit as `fit$eval_budget_spent` and
  `fit$evaluation_only`. A `.fitrx` saved by an older ferx loads with both set
  to `FALSE`. **`fit$converged` is unchanged.** A `maxiter = 0` fit reads
  `NOT CONVERGED   (evaluation_only)`. Two related changes from the same
  ferx-core release: a standalone `imp_eval_only` / `agq_eval_only` run now
  reports `covariance_status` `"not_requested"` instead of `"failed"`, and the
  multi-start note "k of n starts failed" is now an `info` warning (category
  `multi_start`) instead of a critical one, so it no longer flags a healthy fit.
