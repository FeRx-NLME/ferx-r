- **Engine fixes from ferx-core `b259dd10..3f87757e`** (#681). Estimates,
  OFVs or standard errors change for the models each item names:

  - **IOV fits with a time-to-event, binary or CTMM endpoint optimise the
    right objective**
    ([ferx-core #2482](https://github.com/FeRx-NLME/ferx-core/pull/2482)):
    under IOV the FOCE/FOCEI marginal left out the endpoint's data term that
    the EBE search included. Their OFV and estimates change.
  - **The FOCEI objective of a non-Gaussian model with etas is smooth in
    theta** ([ferx-core #2437](https://github.com/FeRx-NLME/ferx-core/issues/2437),
    [#2445](https://github.com/FeRx-NLME/ferx-core/pull/2445)): the
    eta-Hessian of analytic-family TTE, binary and time-homogeneous CTMM data
    terms is exact instead of a finite difference that was mostly round-off.
    OFVs of these models shift slightly, and on a flat direction the point an
    optimizer stops at can move.
  - **The M3 (BLOQ) likelihood uses an accurate normal CDF**
    ([ferx-core #2482](https://github.com/FeRx-NLME/ferx-core/pull/2482));
    M3 fits' OFVs move in the 7th digit.
  - **`method = "gn"` on a model with IOV no longer stops near its initial
    estimates while reporting convergence**
    ([ferx-core #2455](https://github.com/FeRx-NLME/ferx-core/issues/2455),
    [#2516](https://github.com/FeRx-NLME/ferx-core/pull/2516)):
    `warfarin_iov` ended 22.9 OFV above the optimum and now stops 0.013 above
    it.
  - **An IOV occasion that only an `EVID = 3`/`4` reset row carries gets its
    own kappa**, not kappa = 0, as NONMEM estimates an `ETA` for it (the
    objective now matches NONMEM's to 1.6e-8, where it sat 40 OFV units off);
    an unlabelled reset, pk-only or dose row runs under kappa = 0, and such a
    subject on an ODE model no longer falls back to finite-difference
    gradients ([ferx-core #1153](https://github.com/FeRx-NLME/ferx-core/issues/1153),
    [#2494](https://github.com/FeRx-NLME/ferx-core/pull/2494)).
  - **A fit that ends above its own starting objective is no longer reported
    converged**, including one restarted off the log-packing floor or after a
    stall or basin shift: `W_ABOVE_START` is now judged once per fit (per
    stage in a chain) against the fit's first evaluation
    ([ferx-core #2461](https://github.com/FeRx-NLME/ferx-core/issues/2461),
    [#2499](https://github.com/FeRx-NLME/ferx-core/pull/2499),
    [#2517](https://github.com/FeRx-NLME/ferx-core/pull/2517)).
  - **`ferx_sir()` on an ODE model with IOV re-solves a subject whose warm
    inner start was rejected from a cold start** and scores the draw from it,
    instead of scoring the unoptimised start; a draw with a subject rejected
    even cold gets weight 0 and is counted in the all-draws-rejected error
    ([ferx-core #2382](https://github.com/FeRx-NLME/ferx-core/issues/2382),
    [#2489](https://github.com/FeRx-NLME/ferx-core/pull/2489)).
  - **`W_NONFINITE_OBJECTIVE` reads its label from the subjects** ("at the
    divergence sentinel" or "too large to be a fit"), and when only the sum of
    usable contributions fails it lists the ten largest; its details gain
    `reason_read_from` and `largest_subjects`
    ([ferx-core #2265](https://github.com/FeRx-NLME/ferx-core/issues/2265),
    [#2413](https://github.com/FeRx-NLME/ferx-core/pull/2413)).
  - **A parameter assigned inside an `if { ... } else { ... }` block in
    `[individual_parameters]` gets each branch's derivative**, so initial
    estimates read which random effect it uses
    ([ferx-core #2471](https://github.com/FeRx-NLME/ferx-core/issues/2471),
    [#2495](https://github.com/FeRx-NLME/ferx-core/pull/2495)).
