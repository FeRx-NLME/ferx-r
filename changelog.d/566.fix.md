- **`fit$estimates` / `ferx_estimates()` refuse an `eta_param_types` or
  `kappa_param_types` of the wrong length** with a `ferx_fit_field_error`
  naming the field, the same rule `print()` applies (#562). The `scale`
  column used to read the vector by position, so one that was too long
  labelled each random effect with another's scale and no error, and one that
  was too short gave `NA`. A `NULL` or empty field (a fit from before
  ferx-core #1643) still gives `NA` for every row. Only a hand-edited fit can
  reach this: rebuilding its estimates (e.g. `ferx_covariance()`) now refuses
  it instead of reporting a misaligned table
  ([#566](https://github.com/FeRx-NLME/ferx-r/issues/566)).
