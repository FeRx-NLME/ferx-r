- **A SAEM fit's `ofv` is now NONMEM's SAEM objective, and its `aic` / `bic`
  are `NA`** (#757, ferx-core
  [#2973](https://github.com/FeRx-NLME/ferx-core/issues/2973), ferx-core pin
  moved to `9c64c1e0`). The SAEM objective (SAEMOBJ) is what NONMEM prints for
  `$EST METHOD=SAEM`. It is not a likelihood, so it must not be compared across
  models or with a FOCE/FOCEI fit. SAEM OFVs from earlier versions were
  FOCE/Laplace values. `settings = list(saem_ofv = "imp")` reports the
  importance-sampled -2 log L instead (with its Monte-Carlo SE), `"agq"` an
  adaptive-quadrature one, and `"focei"` the previous value. A
  `c("saem", "imp")` chain with `imp_eval_only = TRUE` reports the
  importance-sampled value too, and a mixture model falls back to it with a
  warning. The new `fit$saem_objective` says which one `ofv` is and keeps the
  FOCE/Laplace value as `foce_ofv`. `print()`, `summary()` and `ferx_runlog()`
  name the objective and show AIC/BIC as `n/a` (`NA` in the run log), and
  `ferx_bic()` returns `NA` with a warning for a SAEM-objective fit. A VI fit
  with no OFV now has `NA` instead of `NaN` for `aic` and `bic`.

  **Every model search stops on a SAEM-objective candidate.** `ferx_modelsearch()`,
  `ferx_covsearch()`, `ferx_iivsearch()`, `ferx_iovsearch()`, `ferx_ruvsearch()`,
  `ferx_globalsearch()` and `ferx_amd()` end with an error naming the
  candidate. Add `saem_ofv = imp` (or `agq` / `focei`) to the model's
  `[fit_options]` to search a SAEM model.

  Other engine changes in this pin that reach R:

  - `fit$gradient_method_outer` / `_inner` read `"analytic"` where they read
    `"analytic (Dual2)"` (ferx-core #2949). Bundles saved earlier keep the old
    label. Gauss-Newton fits (`"gn"`, `"gn_hybrid"`) report `"analytic"` where
    they reported `"finite differences"` (ferx-core #2786).
  - `ferx_load_fit()` reads a `null` number in a bundle's `fit.json` as `NaN`
    in its place, the spelling ferx-core writes a non-finite value in, where it
    used to refuse the bundle (ferx-core #2786).
  - `covariance_method = "s"` and `"rsr"` standard errors move on every
    FOCE/FOCEI fit with random effects: the score is now each subject's exact
    total derivative, and `"s"` reproduces NONMEM's `MATRIX=S` (ferx-core
    #2974).
  - A variance the default optimizer drove far below its initial value is
    re-inflated before the fit reports convergence, so some FOCE/FOCEI
    estimates and OFVs move (ferx-core #3005).
  - `SS=1` infusions longer than their interval are at steady state on every
    engine. The closed-form, ODE and SDE paths reported up to 98% too little
    drug for them before (ferx-core #2786).
  - Count endpoints (`[count_model]`, Poisson / negative binomial) can be
    fitted, simulated and predicted from a model file (ferx-core #2877).
