- **Engine features from ferx-core `3f87757e..0703293c`** (#686):

  - **Time-to-event residuals in `fit$sdtab`**
    ([ferx-core #901](https://github.com/FeRx-NLME/ferx-core/issues/901),
    [#2509](https://github.com/FeRx-NLME/ferx-core/pull/2509)): every TTE
    record gets a row after the Gaussian and binary rows, with `COXSNELL`,
    `MARTINGALE`, `DEVIANCE` and `PIT` at the subject's EBE (delayed entry,
    clock-forward and clock-reset RTTE, competing risks); `DV` is the event
    indicator and `PRED`/`IPRED` are `NaN`. `fit$subject_summary` gains
    `n_obs_tte`, each subject's TTE rows. `ferx_save_fit()` does not keep
    these rows and warns (`ferx_tte_rows_dropped_warning`); a reloaded fit's
    sdtab has the Gaussian and binary rows only
    ([ferx-core #911](https://github.com/FeRx-NLME/ferx-core/issues/911)).
  - **`ferx_simulate_adaptive()` accepts an `auc_target` metric on subjects
    with `EVID = 3`/`4` resets**
    ([ferx-core #943](https://github.com/FeRx-NLME/ferx-core/issues/943),
    [#2546](https://github.com/FeRx-NLME/ferx-core/pull/2546)): the window AUC
    is integrated on the run's own trajectory, with a node on each side of
    every dose, reset and infusion end, so a bolus or reset inside a decision
    window is exact (a mid-window bolus carried up to about 1% bias before).
    Attainment on smooth windows moves by up to about 1e-4 relative.
    Time-varying covariates, `TIME` in the PK and IOV are still refused with
    `auc_target`. The attainment itself now reaches R as
    `$metrics$AUC_TARGET_ATTAINMENT`, the fraction of windows between
    consecutive decisions whose AUC fell inside the `auc_target` band (`NA`
    without one); before, R dropped it.
  - **Faster covariance step and AGQ fits**
    ([ferx-core #1564](https://github.com/FeRx-NLME/ferx-core/issues/1564),
    [#2481](https://github.com/FeRx-NLME/ferx-core/issues/2481),
    [#2526](https://github.com/FeRx-NLME/ferx-core/pull/2526)): the exact
    covariance step runs 1.2-1.4x faster, and an NLopt fit that retries or
    restarts runs it once instead of once per attempt; an ODE fit with
    `method = "laplace"`, `n_agq = 3` runs about 1.9x faster. The engine's
    gradient tape buffers are released when a fit ends, so an R session no
    longer holds each thread's largest recording.
