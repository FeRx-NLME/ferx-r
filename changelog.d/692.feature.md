- **Engine features from ferx-core `0703293c..497f918b`** (#692):

  - **Adaptive dosing can change the dosing interval, not only the dose**
    ([ferx-core #945](https://github.com/FeRx-NLME/ferx-core/issues/945),
    [#2563](https://github.com/FeRx-NLME/ferx-core/pull/2563),
    [#2575](https://github.com/FeRx-NLME/ferx-core/pull/2575)): the
    `[adaptive_dosing]` block takes a ladder, `intervals = [12, 24, 36]`, a
    `start_interval = 24`, and the rule effects `lengthen` / `shorten`, alone
    or after one dose effect (`when signal > 20 : decrease 25%, lengthen`).
    The review grid `at` stays fixed; on an `at = every S ...` grid each
    interval must be a whole multiple of `S`. Grid points that are not due are
    logged with `OUTCOME = "not_due"` and what the monitor read.
    `ferx_simulate_adaptive()` gains `$decisions$INTERVAL` (the interval in
    force after the decision, `NA` without a ladder) and `$metrics$N_NOT_DUE`.
  - **`ferx_simulate_adaptive()` runs a base regimen with `EVID = 3`/`4`
    resets under time-varying covariates and IOV**
    ([ferx-core #932](https://github.com/FeRx-NLME/ferx-core/issues/932),
    [#2556](https://github.com/FeRx-NLME/ferx-core/pull/2556)); it was refused
    with `E_ADAPTIVE_UNSUPPORTED`. **`auc_target` works with time-varying
    covariates, `TIME` in the PK and IOV**
    ([ferx-core #943](https://github.com/FeRx-NLME/ferx-core/issues/943),
    [#2555](https://github.com/FeRx-NLME/ferx-core/pull/2555)).
  - **A profiled theta level block fits under `method = "laplace"` and under
    `n_agq > 1`**
    ([ferx-core #2107](https://github.com/FeRx-NLME/ferx-core/issues/2107),
    [#2550](https://github.com/FeRx-NLME/ferx-core/pull/2550),
    [#2561](https://github.com/FeRx-NLME/ferx-core/pull/2561)), reaching the
    unprofiled fit's optimum and standard errors. `foce` with `n_agq > 1`,
    which ignores `n_agq`, is no longer refused.
  - **Faster fits**
    ([ferx-core #2549](https://github.com/FeRx-NLME/ferx-core/issues/2549),
    [#2551](https://github.com/FeRx-NLME/ferx-core/pull/2551),
    [#2542](https://github.com/FeRx-NLME/ferx-core/issues/2542),
    [#2543](https://github.com/FeRx-NLME/ferx-core/pull/2543),
    [#2507](https://github.com/FeRx-NLME/ferx-core/issues/2507),
    [#2515](https://github.com/FeRx-NLME/ferx-core/pull/2515)): FOCE/FOCEI
    fits take up to 60% fewer outer iterations (inner solves start at the
    predicted modes); IOV fits up to 5.9x fewer instructions; closed-form fits
    on time-varying covariates about a third faster; an unprofiled L-BFGS /
    SLSQP fit skips a second verification leg that gained nothing.
    Estimates are the same optimum; OFVs can move within the optimizer's
    tolerance.
  - **SAEM: a one-line additive typical value is mu-referenced**
    ([ferx-core #2544](https://github.com/FeRx-NLME/ferx-core/issues/2544),
    [#2553](https://github.com/FeRx-NLME/ferx-core/pull/2553)):
    `BASE = TVE0 + PLACEBO + ETA_E0` gets the same closed-form update as
    `E0 = TVE0 + ETA_E0`, so SAEM on `mbma_placebo` lands at the FOCEI
    minimum. Under a `[mixture]`, SAEM now warns about an additive
    mu-referenced theta it cannot shift
    ([ferx-core #2548](https://github.com/FeRx-NLME/ferx-core/issues/2548),
    [#2565](https://github.com/FeRx-NLME/ferx-core/pull/2565)).
  - **New fit warning `W_NN_UNSCALED_INPUT`** names each `[covariate_nn]`
    input whose centred and scaled data saturate a hidden unit at the
    initial weights
    ([ferx-core #2549](https://github.com/FeRx-NLME/ferx-core/issues/2549),
    [#2551](https://github.com/FeRx-NLME/ferx-core/pull/2551)).
