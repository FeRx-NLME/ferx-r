- **ferx now builds against ferx-core `5bd862b8`**, up from `59a4fe3f`.
  These engine changes reach R:

  - **A `theta NAME[COL, ...]` level block fits beside kappas at nested
    levels**
    ([ferx-core #2034](https://github.com/FeRx-NLME/ferx-core/issues/2034),
    [#2325](https://github.com/FeRx-NLME/ferx-core/pull/2325)). A block whose
    levels each lie inside one study or one arm of a nested model was refused
    with `E_NESTED_LEVEL_THETA_BLOCK_UNSUPPORTED`. The binder now measures each
    kappa on the groups of its own level, so such a block binds, or is refused
    with `E_THETA_LEVEL_BINDING` naming what it absorbs, as with one level.
    The old code is no longer raised. A block keyed on `TIME`, which the old
    check let through unchecked, is now checked too, and its fit can move: on
    the bundled `nested_levels` example with `theta PL[STUDYID, TIME]` on the
    baseline, OFV -21.007 becomes -122.680.
  - **A `[STUDY, TIME]` block keeps a random effect that only one arm reads**
    ([ferx-core #2131](https://github.com/FeRx-NLME/ferx-core/issues/2131),
    [#2305](https://github.com/FeRx-NLME/ferx-core/pull/2305)). On
    `mbma_placebo`, an `ETA_EM` on the drug effect (read by the active arm
    only) was refused as absorbed together with `ETA_E0`; it now fits
    (OFV 97.0720).
  - **A profiled fit no longer stops "converged" short of its optimum**
    ([ferx-core #2285](https://github.com/FeRx-NLME/ferx-core/issues/2285),
    [#2327](https://github.com/FeRx-NLME/ferx-core/pull/2327)). With no
    `outer_ftol` set, the outer loop of a model with a `profile`d block stops
    on a relative change of `1e-8` instead of `1e-6`. `mbma_placebo` profiled
    reaches OFV 97.07003682 (was 97.07003796), 6.6e-7 above the unprofiled
    fit's 97.07003615 (was 1.8e-6).
  - **Refusals only `ferx_fit()` raised now carry `e$code`**
    ([ferx-core #1788](https://github.com/FeRx-NLME/ferx-core/issues/1788),
    [#2321](https://github.com/FeRx-NLME/ferx-core/pull/2321)):
    `E_MIXTURE_METHOD`, `E_RTTE_RECORDS`, `E_BINARY_STATE`, `E_CTMM_RECORDS`,
    `E_LTBS_UNSUPPORTED`, `E_IIV_ON_RUV_SHARED_ETA`, `E_IIV_ON_RUV_METHOD`,
    `E_IOV_SINGLE_OCCASION`, `E_AGQ_GRID_TOO_LARGE` (the quadrature grid under
    IOV) and `E_DATA_PATH_MISSING`. `ferx_model_validate()` now reports the
    mixture-method, `iiv_on_ruv` and endpoint-record refusals, which it used
    to call valid. Every message reads as before.
  - **`print(fit)`'s THETA BLOCKS line takes its min / median / max from
    ferx-core** (`block_summary`, public since
    [ferx-core #1812](https://github.com/FeRx-NLME/ferx-core/issues/1812)), so
    it cannot drift from the engine's console report and fit YAML. R's own
    copy of that summary is gone; the printed values are unchanged.
  - **A normal SIR proposal (`sir_df = Inf`) is saved in `.fitrx`**
    ([ferx-core #1819](https://github.com/FeRx-NLME/ferx-core/issues/1819),
    [#2309](https://github.com/FeRx-NLME/ferx-core/pull/2309)), written as
    `"df": "normal"` and read back as `Inf`, so `ferx_sir()` on the loaded fit
    repeats it. `ferx_save_fit()` used to warn and save no SIR settings.
    A model file's `[fit_options]` may spell it `sir_df = normal` (or `mvn`);
    `ferx_sir()` takes `sir_df = Inf`.
  - **Regularized `[covariate_nn]` fits report standard errors of the
    penalized objective**
    ([ferx-core #1352](https://github.com/FeRx-NLME/ferx-core/issues/1352),
    [#2330](https://github.com/FeRx-NLME/ferx-core/pull/2330)). With `nn_l2` /
    `nn_smooth` set, the covariance step adds the penalty's curvature, and a
    `W_COV_NN_PENALTY` note says so. `fit$scoring_settings` gains
    `nn_l2_lambda` and `nn_smooth_lambda`; `ferx_covariance()` keeps a
    recorded strength whatever its arguments. A record saved before this
    version reads them as `NA` (unrecorded), and the caller's value stands.
  - **New warnings**: `W_DEGENERATE_CL_V` (category
    `degenerate_clearance_or_volume`, with its own `ferx_get_warnings()`
    guidance) when the final estimates put a non-positive or non-finite `CL`
    or `V` on a record of a closed-form model, which now predicts 0 there on
    both closed-form engines
    ([ferx-core #2104](https://github.com/FeRx-NLME/ferx-core/issues/2104));
    and `W_FREM_DRAWN_ETA` from `ferx_simulate()` on a FREM model simulated
    at drawn etas, whose PK then follows a drawn covariate, not the
    subject's own
    ([ferx-core #2245](https://github.com/FeRx-NLME/ferx-core/issues/2245)).
  - **`W_NONFINITE_OBJECTIVE` names the record and the part of the
    likelihood that failed**
    ([ferx-core #2038](https://github.com/FeRx-NLME/ferx-core/issues/2038),
    [#2266](https://github.com/FeRx-NLME/ferx-core/issues/2266),
    [#2267](https://github.com/FeRx-NLME/ferx-core/issues/2267)): the
    subjects whose own contribution is unusable, the `TIME`, `DV` and `IPRED`
    of the first unusable record, and which term (residual, censored M3,
    random-effect prior, curvature, a non-Gaussian endpoint) broke. A mixture
    fit's sdtab `IWRES`, `CWRES` and per-subject objective are scored under
    each subject's own class.
  - **A warning's structured `details` reach R**
    ([ferx-core #2268](https://github.com/FeRx-NLME/ferx-core/issues/2268)).
    `fit$warning_details` lists the engine warnings that carry a payload
    (`W_NONFINITE_OBJECTIVE`'s full `unusable_subjects`, the high-shrinkage
    ETAs of an `eta_shrinkage` warning, a Durbin-Watson statistic, ODE solver
    counters), and `ferx_get_warnings(as_df = TRUE)` gains a `details` list
    column beside each row; the printed summary names each payload's fields.
    `ferx_save_fit()` writes them to the `.fitrx` `warning_details` slot
    ferx-core reads, and `ferx_load_fit()` restores them from R and engine
    bundles alike, `identical()` to the fit's. `ferx_covariance()` and
    `ferx_sir()` keep them in step with the warnings they drop and add.
  - **Covariance steps and SIR intervals no longer depend on the units of a
    theta with a negative lower bound**
    ([ferx-core #2145](https://github.com/FeRx-NLME/ferx-core/issues/2145),
    [#2179](https://github.com/FeRx-NLME/ferx-core/issues/2179),
    [#2274](https://github.com/FeRx-NLME/ferx-core/issues/2274),
    [#2273](https://github.com/FeRx-NLME/ferx-core/issues/2273)): such a theta
    written in large or small units no longer makes `covariance_method = "s"`
    fail or `"r"` / `"rsr"` understate its SE, and no longer collapses SIR
    intervals. The same holds for an additive eta in a `block_omega`. The
    outer optimizer also scales such a theta by its start value, so a theta
    far from 1 no longer stalls at its initial value while the fit reports
    convergence
    ([#2146](https://github.com/FeRx-NLME/ferx-core/issues/2146),
    [#2272](https://github.com/FeRx-NLME/ferx-core/issues/2272)).
  - **Other fixes**: cold-start `method = "imp"` / `"impmap"` no longer
    collapses (warfarin reaches -286.0 against NONMEM's -285.69;
    [#1365](https://github.com/FeRx-NLME/ferx-core/issues/1365)); an
    OMEGA / KAPPA CV% of 1e6 or more prints to three significant figures in
    scientific notation (`CV% = 7.64e35`) instead of every digit
    ([#1883](https://github.com/FeRx-NLME/ferx-core/issues/1883));
    `W_DERIVED_CMT_TV_ODE` / `_ANALYTICAL` also fire for individual
    parameters that read `TIME`
    ([#1855](https://github.com/FeRx-NLME/ferx-core/issues/1855));
    `fit$gradient_method_inner` reads `"finite differences"` on a
    time-to-event model, and the FD-fallback warning fires
    ([#1861](https://github.com/FeRx-NLME/ferx-core/issues/1861)); a post-hoc
    step on a `.fitrx` of a finite-difference fit saved before ferx records
    `gradient_method` warns that it goes analytic
    ([#1862](https://github.com/FeRx-NLME/ferx-core/issues/1862)); an ODE
    FREM fit's sdtab `IPRED` / `IWRES` on `FREMTYPE > 0` rows report
    theta + eta ([#2259](https://github.com/FeRx-NLME/ferx-core/issues/2259));
    an `if` on a `[covariate_nn]` output takes the right branch in the exact
    gradient ([#2293](https://github.com/FeRx-NLME/ferx-core/issues/2293));
    SIR re-solves each draw's EBEs as the fit did, so at the estimates it
    repeats the fit's objective bit for bit
    ([#2279](https://github.com/FeRx-NLME/ferx-core/issues/2279)); a
    reassigned random effect is labelled by the branch path it takes (SD vs
    CV% row; [#1689](https://github.com/FeRx-NLME/ferx-core/issues/1689)); a
    branch-only helper named like an `[adaptive_dosing]` or `[covariate_nn]`
    word is no longer refused
    ([#1905](https://github.com/FeRx-NLME/ferx-core/issues/1905)).
  - **Faster**: parsing deep chains of `[individual_parameters]`
    intermediates, refusing a level block on large populations, the
    near-zero-theta pre-flight, and exact gradients for covariate networks and
    many-theta models
    ([#1699](https://github.com/FeRx-NLME/ferx-core/issues/1699),
    [#1962](https://github.com/FeRx-NLME/ferx-core/issues/1962),
    [#2291](https://github.com/FeRx-NLME/ferx-core/issues/2291),
    [#2293](https://github.com/FeRx-NLME/ferx-core/issues/2293),
    [#2294](https://github.com/FeRx-NLME/ferx-core/issues/2294)).
  - **Already in the previous pin, not announced until now**:
    `ferx_covariance()` on a fit with a `profile`d level block repeats the
    fit's standard errors bit for bit, live and after
    `ferx_save_fit()` / `ferx_load_fit()`
    ([#2173](https://github.com/FeRx-NLME/ferx-core/issues/2173));
    `ferx_simulate_adaptive()` on a FREM model returns covariate rows as
    `TV + ETA` ([#2156](https://github.com/FeRx-NLME/ferx-core/issues/2156));
    the flat-theta pre-flight hands an IOV subject's kappas to the first
    evaluation, which can move IOV fits at round-off
    ([#2217](https://github.com/FeRx-NLME/ferx-core/issues/2217)).
