- **`ferx_fit()` no longer labels a failure with a validation code that does
  not apply to it** ([#521](https://github.com/FeRx-NLME/ferx-r/issues/521)).
  - A fit interrupted with Ctrl-C now raises a condition of class
    `ferx_cancelled`, and a panic in the engine one of class `ferx_panic`
    (both also `error`), with no `code`. Before, on a model and data where
    validation found exactly one error, either came back as a
    `ferx_engine_error` carrying that unrelated code
    (`ferx_fit: cancelled by user [E_IOV_MISSING_OCC]`).
  - A failure the engine raised without a code is labelled from re-validating
    the model and the data only when the call changes nothing that
    re-validation cannot see. With `settings =`, `ignore =`, `accept =`,
    `ignore_ids =`, `method =`, `covariance =` or another argument that
    overrides `[fit_options]`, only a model that does not parse is still
    labelled that way; any other failure without a text match keeps no code
    rather than a code that may describe a different fit.
