- **A settings record from another ferx no longer blocks a fit.**
  `ferx_load_fit()` used to refuse a whole `.fitrx` bundle whose
  `scoring_settings` or `sir.settings` record named a setting this ferx does
  not know - one written by a newer ferx-core. It now loads the bundle without
  that record, with a warning of class `ferx_settings_record_dropped_warning`
  naming the keys, and `ferx_covariance()` / `ferx_sir()` run on it as on a fit
  that records none. A record that lacks a setting (one saved before the engine
  recorded it, including a fit kept with `saveRDS()`) is read with the value
  that engine ran under, as ferx-core's own reader reads it, instead of being
  refused with `missing key`: `inner_restarts` as its default,
  `inner_screen` as `0` (the screen that fit did not run) and
  `gradient_method` as `"auto"`. An unknown or missing key on a fit in memory
  is still refused by name, and the error now says how to recover: remove or
  restore the key, or set the record to `NULL`
  ([#535](https://github.com/FeRx-NLME/ferx-r/issues/535)).
