- **`?ferx_fit` no longer says eight starts cost the wall time of one**
  (#721): the "Multi-start optimization" section claimed that
  `n_starts = 8` on an 8-core machine takes about as long as a single run. The
  starts share one thread pool with the per-subject loops, so wall time grows
  with `n_starts` unless a single fit leaves cores idle. The section now says
  so and links to the ferx-core multi-start page for when to use it. The
  comments in the bundled `mm_multistart` model and `ex9_mm_multistart.R`
  carried the same claim and are corrected too.
