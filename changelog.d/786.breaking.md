- **Every `ID` column ferx returns is now character: the subject's ID text,
  verbatim** (#786). `fit$sdtab$ID` and the `ID` of `ferx_calc_npde()`'s
  time-to-event scores used to be the engine's number for the subject - the ID
  read as a number, else its position - so `"S1"` came back as `1`, `"001"` as
  `1`, subjects `1` and `1.0` were merged, and joining `ferx_simulate(fit = )`
  (whose `ID` was already text) onto `fit$sdtab` failed. They now hold what
  `fit$subject_ids` holds, as every other `ID` column already did, on fresh and
  reloaded fits alike; a numeric-ID fit's other columns are unchanged.
  `sdtab$ID == 1`, `%in%`, `split()`, `tapply()` and ggplot grouping keep
  working; `sort(unique(sdtab$ID))` now orders as text (`"10"` before `"2"`),
  arithmetic on IDs fails, and a `dplyr` join with numeric-ID data stops with a
  type error. Convert the data's key once: `mutate(ID = as.character(ID))`.
  `ferx_calc_npde(fit, data = <data frame>)` compares IDs as text too, so a
  frame read with plain `read.csv()` turns `"001"` into `1` and is refused,
  naming the first mismatched pair; read it with
  `colClasses = c(ID = "character")` or pass the file path.
