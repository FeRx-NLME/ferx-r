- **Results and parsing that change with ferx-core `48546b91..3cd15863`** (#719):

  - A subscripted read of a data-driven theta level block (`theta P[STUDY]`
    read as `P[STUDY]`, `P[TIME]`, `P[STUDY + 0]` or `P[2]`) is now a parse
    error naming the bare spelling `P`. `P[TIME]` and computed indices used to
    fit silently, at the wrong level. Drop the subscript; the counted form
    `theta P[N]` read as `P[COLUMN]` is unchanged
    ([ferx-core #2744](https://github.com/FeRx-NLME/ferx-core/issues/2744)).
  - `method = "imp"` and `"impmap"` estimates change on any model with a sigma
    or a non-mu-referenced theta: the weighted M-step no longer leaves them at
    their start values. A parameter it still cannot move is named by
    `W_MCEM_MSTEP_FROZEN`, a failed solve gives `W_MCEM_MSTEP_FAILED`, and
    either reports `converged = FALSE`
    ([ferx-core #2718](https://github.com/FeRx-NLME/ferx-core/issues/2718)).
  - `method = "gn"` (and `trust_region`) on Gaussian FOCEI models now steps
    along the exact gradient, so it reaches the FOCEI optimum where it used to
    stop above it (`warfarin_bloq` by 10.6 OFV). Each iteration costs more
    ([ferx-core #2740](https://github.com/FeRx-NLME/ferx-core/issues/2740)).
  - `inner_restarts` now acts on subjects with occasions in a `kappa` model, so
    a subject in a worse EBE mode can move and the OFV can change. Cold solves
    of kappa models cost more; `inner_restarts = 0` restores the old behaviour
    ([ferx-core #2730](https://github.com/FeRx-NLME/ferx-core/issues/2730)).
