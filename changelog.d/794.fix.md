- **`ferx_apply_selection(model = )` now applies the model's `[data_selection]`
  block** (#794): its `ignore`, `accept` and `ignore_subjects` clauses are
  applied first, then the call's, so the preview keeps the records
  `ferx_fit(model, data)` keeps and its `exclusions` match `fit$exclusions`,
  fired rules in the engine's order and listed subjects included. Before, only
  the model's `[data]` column map was read. Fitting such a `ferx_data` with the
  same model no longer lists the model's own clauses as call-time settings in
  `fit$call_settings`. A selection replayed from a fit that used `ignore_ids`
  (`ferx_apply_selection(fit)`) can now be fitted; it used to fail with
  `malformed filter expression 'ignore_subjects: ...'`. Subject IDs are
  matched and reported as the CSV spells them, padding trimmed, as the
  engine does: an ID
  `02` is no longer read as `2`, which made the preview and the replay miss
  `ignore_ids = "02"`.
